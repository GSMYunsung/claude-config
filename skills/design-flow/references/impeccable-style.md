# impeccable.style 참조

출처: https://impeccable.style  
목적: AI 에이전트가 "AI slop"을 생성하지 않도록 설계 어휘와 규칙을 제공하는 도구.

---

## 4가지 제품 모드

디자인 작업 전에 이 네 가지 중 하나를 선언한다. 모드가 레이아웃, 밀도, 모션 방향을 결정한다.

| 모드 | 설명 | 이 프로젝트에서 해당하는 페이지 |
|------|------|-------------------------------|
| **Persuade** | 방문자를 행동으로 이끄는 페이지. 전환 흐름이 최우선 | 홈 히어로, 프로젝트 소개 |
| **Operate** | 사용자가 반복 작업을 효율적으로 수행하는 인터페이스 | 해당 없음 (대시보드 아님) |
| **Read** | 정보를 편안하게 소화하는 페이지. 가독성이 최우선 | 블로그 포스트 |
| **Experience** | 방문자가 몰입하는 감각적 인터페이스 | 포트폴리오 메인, About |

## okLCH 컬러 시스템

impeccable.style은 hex 대신 `oklch()` 색공간을 사용한다.  
**이유:** 인간 시각에 균일하게 지각되므로 대비비 예측이 정확하고, 같은 lightness 값이면 실제로 같아 보인다.

```css
@theme {
  --color-bg:      oklch(98% 0.005 82);   /* 거의 흰색, 따뜻한 기운 */
  --color-surface: oklch(96% 0.008 82);
  --color-text:    oklch(15% 0.01 260);   /* 거의 검정 */
  --color-accent:  oklch(72% 0.18 200);   /* 채도 있는 강조색 */
  --color-muted:   oklch(55% 0.01 260);
}
```

hex 사용 시 대비비 계산이 부정확해지는 문제를 피하기 위해 oklch를 기본으로 쓴다.

## 핵심 디자인 원칙

### 1. 하나의 승자 (Hierarchy)
> "제목과 버튼이 시선을 두고 경쟁하면 안 된다. 오직 하나만 승리해야 한다."

각 화면/섹션마다 가장 중요한 요소 하나만 시각적으로 강조한다.  
나머지는 조용히 지원한다.

### 2. 한 화면, 한 액션
CTA가 여러 개면 아무것도 클릭하지 않는다.  
Persuade 모드 페이지에서 특히 중요.

### 3. 목적 먼저
PRODUCT.md 개념: 디자인 전에 "누가, 왜 이 페이지를 보는가"를 한 문장으로 정의한다.  
→ design-flow의 Phase 2 디자인 읽기 선언과 연결.

## Slop 규칙 — 포트폴리오에 특히 위험한 것들

전체 61개 규칙 중 개발자 포트폴리오+블로그에서 자주 발생하는 항목:

### 즉시 제거
| 규칙 | 설명 |
|------|------|
| AI 색상 팔레트 | AI beige (#F4F1EA류), 보라색 그라디언트 조합 |
| 크림/베이지 팔레트 | 따뜻한 크림 배경 + 고대비 세리프 + 테라코타 — AI 기본값 |
| 이탤릭 세리프 디스플레이 제목 | 고급스러운 척하는 AI 기본 선택 |
| 그래디언트 텍스트 | 보라→핑크 또는 청→보라 텍스트 |
| 래디얼 그래디언트 배경 후광 | 어두운 배경 위 중앙 후광 효과 |
| 어두운 배경의 발광 강조 | glow, bloom 효과 과다 |
| 동일한 카드 그리드 | 3개 equal feature cards |
| 초대형 영웅 제목 | 120px+ 히어로 폰트 (내용 없는 크기 과시) |
| 영웅 메트릭 레이아웃 | 큰 숫자 + 작은 레이블 통계 3개 나열 |

### 타이포그래피
| 규칙 | 설명 |
|------|------|
| 평탄한 타입 계층 구조 | 모든 텍스트가 비슷한 크기 |
| 제목 위의 작은 레이블 | "ABOUT ME" 같은 eyebrow 레이블 남발 |
| 극소 인터페이스 텍스트 | 11px 이하 본문 |
| 대문자 본문 텍스트 | all-caps 남용 |

### 모션
| 규칙 | 설명 |
|------|------|
| "맥박" 상태 점 | pulsing dot 애니메이션 |
| 바운스/탄성 이징 | spring bounce가 UI에 부적절한 곳에 사용됨 |
| 장식용 깜빡이는 커서 | 타이핑 커서 애니메이션 |
| 자동 스크롤 마퀴 | 무한 루프 스크롤 배너 |

### 레이아웃
| 규칙 | 설명 |
|------|------|
| 단조로운 간격 | 모든 섹션이 같은 padding |
| 이전 섹션에 더 가까운 제목 | 제목이 위 섹션에 붙어있고 아래 내용과 멀어 보임 |
| 너무 긴 줄 길이 | 본문 1줄이 80자 초과 |
| 페이지 가장자리에 닿은 본문 텍스트 | 좌우 패딩 없음 |

### 일반
| 규칙 | 설명 |
|------|------|
| 일반적인 마케팅 주장 | "Innovative", "Passionate developer" 같은 빈 카피 |
| 플레이스홀더 스타일 일러스트레이션 | 의미 없는 장식 일러스트 |

## DESIGN.md 개념

impeccable.style은 프로젝트 루트에 `DESIGN.md`를 두고 에이전트가 항상 참조하게 한다.  
design-flow 스킬에서는 이 역할을 `_workspace/design-flow/brief.md`가 대신한다.

구조 참고:
```markdown
## Color
oklch 값 + 역할

## Type
서체명 · 크기/weight 조합

## Shape
border-radius 기본값

## Components
반복되는 컴포넌트 목록
```
